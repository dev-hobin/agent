# Developer Judgment Policies

Developer separates dynamic semantic judgment from mutation authority.

```text
question
→ one bundled Developer capability
→ optional CompiledJudgmentPolicy
→ exact current-branch material
→ contribution coverage
→ semantic conclusion

separately

bounded implementation question
→ AuthorizedChange
→ Pi mutation
→ ImplementationLanding
→ reroute and verification obligations
```

## Ownership

- `SKILL.md` owns the complete capability method.
- Optional `judgment.json` owns only capability `when`/`unless` and conditional
  packaged reference `{path, when}` statements.
- Pi owns visible skill/tool/context discovery and physical acquisition.
- The model supplies task-specific question text and semantic nominations.
- Judgment owns exact policy parsing, owner binding, selection, sealing,
  contribution assurance, and closure.
- Developer owns method selection, question gates, mutation authorization,
  landing, reroute, and verification debt.

Project skills remain normal Pi peers and may contribute observed method or
guidance context. They do not become Developer-owned methods and cannot grant
mutation authority.

## Optional policy

Seven bundled skills have conditional packaged references and own a policy:

```text
abstraction-review
model
naming-judgment
schedule
signal
sketch
verify
```

Four complete skills have no packaged conditional references and own no policy:

```text
adversarial-eval
doctor
specify
visualize
```

Absence is normal. A present malformed policy fails closed.

```json
{
  "specVersion": "0.1",
  "when": [
    "Caller-facing operations or ownership still need an implementable shape."
  ],
  "unless": [
    "A concrete candidate already exists and only its stability must be reviewed."
  ],
  "references": [
    {
      "path": "references/design-levels-and-boundaries.md",
      "when": [
        "A dependency boundary needs explicit caller, owner, hidden-mechanism, and direction distinctions."
      ]
    }
  ]
}
```

Root `unless` wins. Each reference is independent and remains optional. The
model-visible `## Context Directions` section is generated byte-for-byte from a
present policy. Skills without policy have no generated section.

## Runtime operations

### `developer_open_judgment`

Selects one bundled skill, loads its complete method, derives owner identity,
and compiles its optional policy. The task-specific question is already dynamic;
there is no authored `question_id`.

### `developer_open_context_sources`

Opens one bounded batch of exact Pi-visible Skill IDs for the active judgment.
Each method and optional co-located policy becomes visible before applicability.
The operation may be called again when new evidence reveals another relevant
Skill; successful batches extend the same `ActiveJudgment` rather than starting
another lifecycle.

### `developer_conclude_judgment`

Resolves source applicability, exact inventory, compact `branchResultId`, and user-event nominations.
It then atomically selects/seals material, records contributions, assesses
conflicts/limitations/sufficiency, and creates one semantic outcome. It accepts
no mutation fields.

At the model boundary:

```text
nominationId
+ exact inventory/branch/user locator
→ selected materialId
→ useAs + concrete contribution + assurance
→ derived contributionId
→ outcome citation by contributionIndex
```

`branchResultId` is a compact alias for one exact current-branch Pi tool
call/result. Alias collisions fail closed. Persisted basis retains material,
content, question, policy, selection, coverage, and outcome identities.

### `developer_authorize_change`

Records one movement, stable landing, verification target, and optional real
refinement boundary or bounded trusted-compiler gap. Only this value permits
bounded mutation.

### `developer_record_landing`

Requires exact authorization and non-empty changed paths. Landing is not a
completion or verification claim.

## Assurance

- `agent-asserted`: agent-owned semantic relation;
- `domain-verified`: requires matching selected typed evaluator evidence;
- `user-accepted`: requires the matching selected user event.

Prose cannot manufacture typed authority. Prepared guidance cannot override a
project constraint. A user decision cannot rewrite an observed fact.

## Replay and protocol

`developer/v7` persists immutable `ActiveJudgment`, `AuthorizedChange`,
`JudgmentConcluded`, and `LandingRecorded` variants. A context basis binds:

```text
judgmentId
policySha256? + questionSha256
opened context-source descriptor/policy/applicability identities
selectionSha256 + sealedContextSha256
coverageSha256 + outcomeSha256
material identities + contribution summaries
conflict IDs + limitation IDs
```

Unsupported v6 history receives a restart diagnostic rather than
reinterpretation.
