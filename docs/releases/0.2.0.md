# Standards-first packages: 0.2.0 release preparation

Prepared on 2026-10-27. This change prepares the source packages; npm publication,
registry verification, and dist-tag updates are separate release operations.

| Package | Previous npm version | Prepared version | Bundled Skills |
| --- | --- | --- | --- |
| `@hobin/developer` | `0.1.20` | `0.2.0` | 17 |
| `@hobin/learning` | `0.1.1` | `0.2.0` | 5 |

Both packages move to the next pre-1.0 minor because directly configured Pi
extension source paths change. Package versions do not change the version of our
reference-policy schemas or the pinned upstream Agent Skills baseline.

## What changes

- Canonical methods are Agent Skills bundles; Pi is an optional integration, not
  a prerequisite for reading or using the instructions.
- Pi runtime integration moves from `extensions/` to `adapters/pi/`, and package
  manifests expose the new locations.
- Learning's Pi peers become optional so consumers do not need to install a Pi
  runtime just to consume the Skill resources.
- English and Korean usage documentation distinguish portable methods, our own
  conditional-reference convention, and host features.
- Development checks and CI separate standard/portable resources from Pi
  integration. The pinned upstream reference validator is authoring-only.

## Migration

| Consumption path | Required action |
| --- | --- |
| Pi package installation | Update the package after npm publication; the manifest handles discovery |
| Skill directories consumed by another Agent Skills host | Copy or expose the complete `skills/<name>/` bundle, including supporting files |
| Direct Developer extension path | Replace `extensions/skill-references/index.js` with `adapters/pi/skill-references/index.js` |
| Direct Learning extension path | Replace `extensions/learning.ts` with `adapters/pi/learning.ts` |
| Direct Learning TUI imports | Replace `extensions/tui.ts` with `adapters/pi/tui.ts` |
| Pi resource selection | Keep existing filters such as `"extensions": []` or `"skills": []` |

The Pi adapter bodies, command behavior, and bounded passive metadata disclosure
are unchanged. Developer's normal `SKILL.md -> references.json -> selected
reference` path and Learning's generated `Context Directions` remain available
without a custom host loader. Neither package acquires a shared agent loop,
mandatory workflow, or persistence service.

## Release verification

Before publishing, run `pnpm check` with the authoring environment activated and
inspect both packed artifacts. The portable checks consume actual npm packs as
relocated Skill directories without an adapter or package manifest; Pi checks
load both actual packed packages through Pi's resource loader.

Publish only after authorization and npm authentication. Do not treat prepared
manifest versions or a successful pack as registry publication. After publishing,
verify each exact version and its `latest` dist-tag on npm independently. No
GitHub release or npm publication is implied by merging this preparation.

Structural checks do not prove Claude/Codex live-model selection quality. The
four standalone Skills under the repository's `skills/` directory remain outside
both npm package catalogs.
