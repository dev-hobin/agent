# 0.3.0: focused entry points, shared lenses, measured Skills

**Status: prepared on branch `restructure/p1-hygiene`; not released.** Model
evaluations (plan step P4) have not been run, npm publication and pushing need
separate approval, and the merge or retirement decisions that evaluations may
produce (for example `conceptualize` and `patternize`) are still open.

## Breaking changes

- The marketplace is renamed from `hobin-agent` to `hobin`. Plugin IDs become
  `<plugin>@hobin`.
- `hobin-developer` (`@hobin/developer`) is retired. Its 17 Skills are replaced by
  four focused plugins. The old Skills stay in `archive/developer-0.2.2/` for
  provenance and are not packaged.
- The standalone Skills `claim-evidence`, `delegation-gate`, `learning-checkpoint`,
  and `work-slice`, and the `agents/inspectable-collaboration.md` fragment, are
  retired into the places listed below.
- The Developer Pi adapter that disclosed `references.json` is retired: the new
  Skills list each reference and its read condition in `SKILL.md`.

Lenses ship inside the Skills that use them (`reviewing-code/references/perspectives/`,
`developing-features/references/lenses/`) and are authored once in `sources/lenses/`.

## Migrating an installation

```sh
# Claude Code
claude plugin uninstall hobin-developer@hobin-agent
claude plugin marketplace remove hobin-agent
claude plugin marketplace add /absolute/path/to/agent --scope user
claude plugin install hobin-review@hobin --scope user
claude plugin install hobin-feature@hobin --scope user
# Codex
codex plugin remove hobin-developer@hobin-agent
codex plugin marketplace remove hobin-agent
codex plugin marketplace add /absolute/path/to/agent
codex plugin add hobin-review@hobin
codex plugin add hobin-feature@hobin
```

These subcommands exist in Claude Code 2.1.314 and Codex CLI 0.165.0, but the
repository's probes do not exercise an upgrade from an existing 0.2.x install. `hobin-learning` users
reinstall it from the renamed marketplace.

## Other changes

- Descriptions use a third-person summary, `Use when`, and `Not for`; Gotchas hold
  only observed failures (see the [standards register](../standards.md)).
- Entry points are explicit-use: the description says so, and
  `agents/openai.yaml` turns off implicit invocation in Codex.
- Each package gains `evals/` (regression and trigger cases for `claude plugin eval`,
  graded only by deterministic graders) and, where outcomes need hidden tests,
  `benchmarks/` for `evaluating-skills/scripts/benchmark.mjs` (dry run unless
  `--execute`). Fixtures are synthetic. npm packs exclude both.
- `pnpm check` adds `check:sources` (lens copies must match `sources/lenses/`),
  `check:evals` (generated trigger cases match their sources), and model-free checks of
  every eval case, grader pattern, scaffold, and hidden test.

## Verification scope

  pass on Claude Code 2.1.314 and Codex CLI 0.165.0 (model-free; see
