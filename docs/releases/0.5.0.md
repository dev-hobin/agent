# 0.5.0: entry skills the agent can pick on its own

**Status: released on `main`, 2026-11-02.**

| Plugin | Version |
|---|---|
| `hobin-feature` | 0.4.0 → 0.5.0 |
| `hobin-review` | 0.3.0 → 0.5.0 |
| `hobin-stances` | 0.3.0 → 0.5.0 |
| `hobin-learning` | 0.3.0 → 0.5.0 (plugin hooks on Claude Code) |
| `hobin-skill-eval` | 0.3.0, unchanged |

## Changes

- `developing-features`, `reviewing-code`, and `applying-stances` were explicit-only.
  Now the agent can start them on its own when a request fits; starting them by name
  still works.
  - Claude Code: `disable-model-invocation` is removed.
  - Codex: `policy.allow_implicit_invocation: false` is removed.
- Each of the three capabilities gets a `triggers.yaml`: 10 requests that should start the
  skill and 10 near misses that should not. On Claude Code they run as trigger evals.
- Descriptions now say when to use each skill instead of "only when explicitly asked".
  - `developing-features` also says to start before exploring the code.
- Guarantee G1 ("starts only when the user asks explicitly") is removed from the three
  specs. The other guarantee IDs are unchanged. `applying-stances` still writes nothing
  before approval (G2), so starting on its own cannot change agent instructions
  unnoticed.

- On Claude Code, result hooks move from skill frontmatter to each plugin's
  `hooks/hooks.json`, as on Codex.
  - A frontmatter hook was registered only after its skill was invoked. A plugin hook runs
    in every session, however the skill started.
  - The hook scripts check only results written in the session, so other sessions are
    left alone.
  - The `hobin-feature` Stop hook is now one byte-identical script on both hosts.
  - Affected plugins: `hobin-feature`, `hobin-review`, `hobin-stances`, and
    `hobin-learning`, whose skills already were model-selectable.

Why: under autonomous use, an explicit-only skill never runs unless a person names it,
so its guarantees (scenario and control-model gates, verification, report checks) were
missing from exactly the unattended work they exist for.

What is deterministic and what is not:

| Deterministic: holds every time | Probabilistic: the model's choice, measured as a rate |
|---|---|
| The invocation policy (no `disable-model-invocation`, no `allow_implicit_invocation: false`) | Whether the agent picks a skill for a request that fits |
| Descriptions and trigger sets match the specs, with an eval case per query (`check.mjs`) | Whether it leaves near misses alone |
| A record or result written in a session is checked by the plugin hooks before the agent finishes, whether or not the skill was invoked | Whether the agent writes a record when the work needs one |

The right column is a benchmark, tracked as a rate over runs, not a pass/fail gate.
Project instructions (`AGENTS.md`) can narrow it, for example: "use developing-features
for slices with external jobs, cancellation, or late results".

## Upgrading

```sh
claude plugin marketplace update hobin
claude plugin update hobin-feature@hobin   # and hobin-review, hobin-stances, hobin-learning
codex plugin marketplace upgrade hobin
```

The `hobin-feature` Stop hook script changed, so in Codex, open `/hooks` in a new session
and trust it again. Claude Code needs a restart or `/reload-plugins` to pick up the plugin
hooks.

## Verification

Deterministic, without models:

- `pnpm check` (93 tests), `pnpm check:claude`, and `pnpm check:install -- claude|codex`
  pass on Claude Code 2.1.314 and Codex CLI 0.166.0.
- `tests/hooks.test.mjs` runs each hook on both hosts and fails if a skill registers a
  frontmatter hook. It also checks that the feature Stop hook leaves alone a session that
  wrote no record.
- One live Claude Code session (Haiku, $0.006) wrote an incomplete
  `acceptance-scenarios.json` without invoking any skill. The plugin Stop hook sent it back
  three times, then let it stop.

Benchmark, Claude trigger evals (`claude plugin eval --tag trigger`, Sonnet, 3 runs per
query, 20 queries per skill):

| Skill | Should trigger | Near misses left alone |
|---|---|---|
| reviewing-code | 30/30 | 30/30 |
| applying-stances | 30/30 | 30/30 |
| developing-features, first description | 27/30 | 30/30 |
| developing-features, released description | 30/30 (one run) | 30/30 |

- The three misses on the first description had the same cause. The agent explored the
  empty workspace first, then asked questions instead of starting the skill.
- The released description adds "Start it before exploring the code". The reason is the
  skill's design: scenarios come before code. One clean run of 60 does not prove the
  change helped; three runs per query cannot tell 2/3 from 3/3 apart reliably.
- Codex has no skill-selection verifier (`plugin-eval`). Its trigger sets are recorded as
  unsupported in `codex/IMPLEMENTS.json`, as for the other model-selectable skills.
- Not rerun: the regression evals. Skill bodies are unchanged. The moved hooks are covered by
  `tests/hooks.test.mjs` and the live session above, not by a model eval.
