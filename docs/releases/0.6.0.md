## Changes

- **Session registry.** At SessionStart the hook creates
  `<start dir>/.hobin-feature/sessions/<session_id>.jsonl` (and `.hobin-feature/.gitignore` = `*`)
  and remembers the start directory in the plugin data directory; later events never locate it from
  their own `cwd`. UserPromptSubmit creates it when SessionStart was missed (Claude:
  `CLAUDE_PROJECT_DIR`; Codex: the event `cwd`).
- **Scripts register, and fail closed.** `scenarios.mjs init | register | run | decline` take the
  session id from `CLAUDE_CODE_SESSION_ID` / `CODEX_SESSION_ID`, find the registry from their working
  directory upward and append `{"file": "<absolute path>", "at": "…"}`; records in other
  repositories register by absolute path. With a session id and no (writable) registry they exit 2
  before creating or running anything and say why (run from the start directory; without active
  hooks pass `--no-gate`). Without a session id they proceed unregistered; `--no-gate` proceeds and
  says no gate covers the record. `check` registers nothing. Records carry no session data. `run`
  hides the session id from the commands it runs.
- **One shared module.** All registry logic is `core/shared/scripts/session-registry.mjs` (no
  hobin-feature specifics; copied next to the skill's scripts by `pnpm sync:core`); `scenarios.mjs`
  and the hook only call it.
- **Edit tools register too:** Claude Write/Edit/MultiEdit of a record file, Codex `apply_patch`
  Add/Update/Move to.
- **Stop gates exactly the registry's records** (a missing one is reported); no directory search.
  With the skill started and an empty registry it names `node "<plugin scripts>/scenarios.mjs"
  init|register|decline …` and the start directory to run them from.
- **Decline is a record.** `scenarios.mjs decline <path> --reason "<why>"` writes and registers
  `{"declined": {"reason", "at"}}`; refused for an empty reason or over a record that is not declined.
  `check` passes it with a reason (and fails one that also holds scenarios). It lifts only the
  "no record yet" obligation.
- **Run state in the record** (`verification.run`), as before.
- **Cleanup.** SessionEnd deletes the registry and the session's plugin data state; Stop prunes
  week-old registries in the start directory and week-old state.
- **Removed:** the plugin MCP server (`records-mcp-server.mjs`, `record-tools.mjs`), `.mcp.json` on
  both hosts, the Codex manifest `mcpServers`, the Claude PreToolUse allow hook. Hooks on both hosts:
  SessionStart, UserPromptSubmit, PostToolUse (Claude: `Write|Edit|MultiEdit|Skill`), Stop,
  SessionEnd; the same script on both.

## Upgrading

- Run `scenarios.mjs` from the directory the session started in, with absolute record paths.
- **Codex:** plugin hooks run only after you trust them with `/hooks`, and again after each update.
  Without them there is no registry, so `scenarios.mjs` stops and says the hooks are not active.
- **Evaluations:** `claude plugin eval` needs no MCP flags (`--allow-tools Bash Write Edit`). Codex
  plugin-eval never installs the plugin, so its runs measure the skill only (the model meets the
  "no registry" message and uses `--no-gate`); the gate is checked by
  `pnpm check:live -- claude|codex`.
