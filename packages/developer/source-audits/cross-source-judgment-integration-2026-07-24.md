## Audit Question

Can the audited insights from *99 Bottles of OOP*, *How to Design Programs*,
*SICP*, *Logic for Programmers*, *Elements of Clojure*, and *Tidy First?* be
combined into source-independent, situation-routed judgment methods without:

- organizing runtime guidance by book or chapter;
- asking the model to synthesize unrelated ideas after load;
- duplicating another skill's construction method;
- erasing source limitations, defects, or Developer adaptations;
- merging independent triggers, artifacts, and stop conditions into one OR-shaped
  route; or
- preserving a document merely because a completed source audit once named it?

## Diagnosed Structural Failure

The first repair stage was faithful source by source but accumulated several
runtime-document defects:

1. `reference-policy.json` routed documents by broad subject and artifact lists,
   but did not identify the exact skill-method step, stop, or handoff.
2. Some references became anthology containers whose sections answered
   independent questions.
3. `abstraction-review/references/recipe-cards.md` copied construction methods
   owned by `signal`, `model`, and `sketch`, creating a shadow skill.
4. `composition-generative-recursion-and-accumulators.md` combined four different
   derivations under one trigger.
5. `generic-operations-and-languages.md` combined additive dispatch with full
   language/evaluator/compiler semantics.
6. `processes-state-and-time.md` combined ordinary generated-process obligations
   with persistent history and ordering.
7. `verifier-selection-and-pass-but-wrong.md` preserved book-labeled calibration
   islands in its operational body.
8. Live routing could prove a document was loaded without proving that its
   insights formed one judgment.

Classification: **vertical structural signal**. The stable concept is a
judgment-integrated route, not a larger reference anthology.

## Integration Standard

Every active skill now has one judgment spine:

```text
observable pressure
-> one core question
-> consequential distinctions
-> inspectable artifact
-> falsifier or stop
-> bounded decision and handoff
```

Every source-derived insight must play exactly one operational role:

```text
trigger recognition
consequential distinction
artifact derivation constraint
falsifier / stop condition
separation / handoff signal
```

Placement rules:

| Insight role | Owner |
| --- | --- |
| always required for the leaf judgment | `SKILL.md` |
| conditionally deepens the same judgment and stop | one routed reference |
| changes question, artifact, owner, or stop | separate route or skill |
| source example, sequence, defect, or edition evidence | source audit / Source Trace |
| no operational role after translation | excluded from runtime guidance |

Strong separation evidence is two or more of: independent trigger, question,
artifact, stop, owner/handoff, or ability to complete independently.

## Separation Decisions

### Retired shadow construction

`skills/abstraction-review/references/recipe-cards.md` is retired. Its legitimate
construction insights already have owning references under `model` or `sketch`.
`abstraction-review` now evaluates promises of an existing candidate and hands
missing construction back to the owning leaf.

### Split model calibration anthology

`worked-models-and-specialized-techniques.md` is replaced by:

- `contract-and-replacement-models.md`
- `relational-constraint-models.md`
- `temporal-behavior-models.md`
- `proof-obligations.md`
- `solver-result-boundaries.md`
- `logic-query-semantics.md`
- `planning-models.md`

Proof is not solver status, query answers are not plans, and each now has one
question, artifact, stop, and handoff.

### Split data-shape-adjacent algorithms

`composition-generative-recursion-and-accumulators.md` is replaced by:

- `composition-by-wishes.md`
- `earned-abstraction.md`
- `generative-recursion.md`
- `accumulator-invariants.md`

Composition does not require an abstraction candidate, and a candidate requires
completed designs rather than merely a wished decomposition. The base data recipe
remains co-required because each route refines a later step of that recipe, not
because all are one recursion topic.

### Split boundary, process, state, genericity, and language

`abstraction-composition-and-state.md` becomes the smaller common kernel
`design-levels-and-boundaries.md`. Environment/participant pressure moves to
`responsibility-and-collaboration.md`; pull-transform-push moves to
`process-shape-and-resources.md`.

`processes-state-and-time.md` is replaced by:

- `process-shape-and-resources.md`
- `state-history-and-order.md`

`abstraction-barriers-and-closure.md` is replaced by:

- `representation-barriers.md`
- `closure-and-conventional-interfaces.md`

`generic-operations-and-languages.md` is replaced by:

- `generic-dispatch-systems.md`
- `meaning-preserving-conversions.md`
- `language-semantics.md`
- `runtime-and-compilation.md`

`responsibility-and-variation.md` is replaced by:

- `responsibility-and-collaboration.md`
- `variation-roles.md`
- `type-transitions.md`
- `selection-and-creation.md`

A caller role can be complete without a type transition or factory. A transition
can preserve meaning without defining a shared role, and a creation boundary can
be judged without redefining either.

- no v0.14 Logic beta defects, predicate-as-implementation claim, unbounded proof

  to EoC;

  universal Pareto/power-law claim, or observer-free reversibility.

Developer adaptations remain labeled where they introduce repository recovery,
production compatibility, migration, rollout, cancellation, capacity, telemetry,
or distributed completion protocols.

## Verdict

**Complete — source-faithful and judgment-integrated after separation repair.**

The runtime organization is no longer a source-shaped anthology. Each routed
reference extends one observable question toward one artifact and stop check;
independent role, transition, selection, representation, closure, process,
state, dispatch, conversion, language, and runtime questions are separable.
`abstraction-review` no longer constructs candidates owned by `sketch`, and
verification calibration is claim/observer/evidence/residual-risk shaped rather
than book shaped.

This verdict supports source fidelity, deterministic runtime integrity, and
finite direct live coverage of all current routes. It does not turn one-trial
samples into route-probability estimates or remove the need for repeated trials
when release confidence depends on model variance.
