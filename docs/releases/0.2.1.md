# Package-owned Claude namespaces: 0.2.1 release preparation

This is a prepared patch release, not an npm publication. Both packages move from
`0.2.0` to `0.2.1`; the already published `0.2.0` artifacts remain unchanged.

## Added metadata

- `@hobin/developer` ships `.claude-plugin/plugin.json` with name
  `hobin-developer`.
- `@hobin/learning` ships the same host metadata path with name `hobin-learning`.
- Plugin version, description, and author match their npm package metadata.
- npm exports include the host manifest; actual packed artifacts are checked.
- The manifest is identity-only and uses the existing default `skills/` layout.
  No runtime, installer, hook, or server is added.

When Claude loads the package roots as plugins, commands are qualified, for
example `/hobin-developer:model` and `/hobin-learning:technical-reading`.
[Loading instructions and guarantee boundaries](../claude-plugins.md) distinguish
this from ordinary Skill installation.

## Unchanged behavior and limits

All canonical Skill names, methods, relative reference paths, and optional Pi
adapter behavior are unchanged. Codex and other Agent Skills hosts can still
consume standalone Skill directories without reading Claude metadata.

`skills add` does not itself apply native Claude plugin namespaces. Previously
installed flat Claude Skills are not removed automatically. This release does
not reserve names globally against arbitrary third-party plugins or promise
cross-host uniqueness for unqualified Skill names.

## Verification

Portable tests enforce scoped, distinct identities; synchronized metadata;
manifest inclusion in npm packs; and rejection of malformed identity conventions.
The optional `pnpm check:claude` uses Claude's manifest validator without a model
request. Standard Skill checks and Pi integration checks remain independent.

Publishing and changing users' global plugin settings require separate action.
