**Status: released on `main`, 2026-11-07 (PR #9).** It builds on 0.6.0 (the hobin-feature
session registry, PR #8) and follows it.

## Why

The review, stances and learning hooks decided "this session's results" by inference: `.md`
names parsed out of shell commands and searched for under the cwd, a `PreToolUse` stamp per
call, file mtimes, the transcript's birth time, `git log` dates to tell a checkout from a
write, and a ledger in `os.tmpdir()`. Each had known misses or false claims. hobin-feature
replaced the same mechanisms with a session registry in 0.6.0; the result hooks now use it too.

## Changes

- **Session registry per plugin.** At SessionStart each hook creates
  `<start dir>/.hobin-<review|stances|learning>/sessions/<session_id>.jsonl` (and a `.gitignore`
  holding `*`) with the shared `core/shared/scripts/session-registry.mjs`, and remembers the
  start directory in the plugin data directory; UserPromptSubmit creates it when SessionStart
  was missed (Claude: `CLAUDE_PROJECT_DIR`; Codex: the event `cwd`). Later events never locate
  it from their own `cwd`.
- **Scripts register, and fail closed.** `check-report.mjs new|check`, `stances.mjs check` and
  `output-contract.mjs new|check` find the registry from their working directory upward with
  `CLAUDE_CODE_SESSION_ID` / `CODEX_SESSION_ID` (every one present is tried) and append the
  file's absolute path. With a session id and no registry they exit 2 before writing or
  checking anything and say why. Without a session id (a person) they proceed unregistered.
  `--no-gate` proceeds unregistered only where no registry is found; where one is found it is
  refused (exit 2). The skills never mention `--no-gate`; only the "no registry" message does.
- **Review starter.** `check-report.mjs new <file>` writes a report skeleton that fails the
  check until it is replaced (TODO: lines, no finding or `No findings`). The review procedure
  starts a report file with it, as learning starts from `output-contract.mjs new`.
- **`stances.mjs block` registers nothing.** It writes no file; the target changes only after
  approval, and the procedure then runs `stances.mjs check <target>`, which registers it. The
  proposal file is registered by `stances.mjs check <proposal file>` (step 4 now writes the
  proposal first, then checks it).
- **Edit tools register results.** Claude Write/Edit/MultiEdit (`tool_input.file_path`) and Codex
  `apply_patch` (Add File, Update File, Move to) are checked at once and registered when the
  plugin's check recognizes a result. The stances hook recognizes a line that opens the block,
  not the marker text anywhere in a file.
- **Stop checks exactly the registry's files** with the plugin's check; a registered file is
  judged as a result even when it no longer looks like one, and a missing one is reported. At
  most three blocks in a row, as before.
- **Cleanup.** SessionEnd deletes the registry and the session's state; Stop prunes week-old
  registries in the start directory and week-old state.
- **Hooks.** SessionStart, UserPromptSubmit, PostToolUse (Claude matcher `Write|Edit|MultiEdit`;
  Codex none), Stop, SessionEnd, with the host named on the command line. `PreToolUse` and
  `PostToolUseFailure` are gone. `hook-input.mjs` stays one file on all three plugins and both
  hosts.
- **Removed from `hook-input.mjs`:** shell-text parsing (`NAMED`, `MENTIONS`, `shellFiles`), the
  `PreToolUse` stamps, mtime/transcript/`git log` dating (`checkedOut`), the `markdownFiles`
  walk and the `os.tmpdir()` ledger.
- **Scenario checks** (`scenario-check.mjs`) run `command_passes` and `script_passes` without
  the session variables, as `scenarios.mjs run` does: a grader is not the session.

## Upgrading

- Run the skills' scripts from the directory the session started in, or below it.
- A result written only by shell redirection, without the skill's script or an edit tool, is
  not checked; the procedures start every result from a script.
- **Codex:** plugin hooks run only after you trust them with `/hooks`, and again after each
  update. Without them there is no registry, so the scripts stop and say the hooks are not
  active. Codex plugin-eval never installs the plugin, so its runs measure the skill only.
- The registry folders (`.hobin-review/`, `.hobin-stances/`, `.hobin-learning/`) appear in the
  start directory and ignore themselves.
