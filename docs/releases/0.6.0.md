## Changes

- **No inference.** The Stop hook no longer reads shell text or walks the tree: PreToolUse stamps,
  record-name parsing of commands, the cwd walk and the git checked-out exemption are gone.
- **Exact registration.** `scenarios.mjs init|run|check <record>` and
  `compile-control-model.mjs --baseline|--changes|--gate <record>` add the record to the session
  ledger themselves, from the host's session id (`CLAUDE_CODE_SESSION_ID`, `CODEX_THREAD_ID`).
  Edit tools still register the exact path they wrote. A record in another repository is gated
  wherever it lives; a file a shell program writes some other way is not the session's.
- **`scenarios.mjs init <path>`** creates the record from the template and never overwrites.
- **Obligation.** Starting developing-features (Claude: the Skill tool or a
  `/developing-features` / `/hobin-feature:developing-features` prompt; Codex: a
  `$developing-features` prompt or reading this plugin's SKILL.md) makes Stop ask for a record.
- **`scenarios.mjs decline --reason "<why>"`** releases that obligation for the session; Stop
  prints the reason. Records already registered must still pass.
- **Run state.** `run` marks results `running`, saves after each one and keeps a temp-dir marker,
  so an interrupted run never leaves earlier passes; `check` and Stop say whether a run is still
  going (pid, start) or was interrupted.
- **Hooks.** Claude: UserPromptSubmit, PostToolUse `Write|Edit|MultiEdit|Skill`, Stop (no Bash
  hooks). Codex: UserPromptSubmit, PostToolUse, Stop. Same script on both hosts.
- **Checks run by `run`** get no session id, so fixtures they create are never the session's.

## Upgrading

Sessions that copied the template by hand now need `scenarios.mjs init`, `run <record>` or an
edit-tool write for the record to count; the skill text says so. `pnpm check`: 182 tests pass, 0 fail. Not run: paid host evals and a
live session with 0.6.0 installed.
