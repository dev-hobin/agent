# 0.4.0: control decision records in developing-features

**Status: released on `main`, 2026-11-02.** Only `hobin-feature` changes (0.3.0 → 0.4.0);
the other plugins stay at 0.3.0.

## Changes

- `developing-features` adds a control-model path for code that handles concurrency,
  cancellation, retries, or late results.
  - Before the change, the agent writes `control-decisions.json` for the current code.
  - The record holds facts and rules, not states. Each fact cites file:line plus a
    `symbol` on those lines. Each rule cites the handler it copies.
  - `compile-control-model.mjs` compiles the record into a state × event table.
  - `--baseline` snapshots the table before the code changes.
- G7, a pass/fail gate (`compile-control-model.mjs --gate`), fails a record when any of
  these hold:
  - evidence does not resolve, or a rule's cited code does not mention its variables;
  - written state has no fact covering it;
  - the model has an error or warning, or an invariant breaks;
  - a finding is not acknowledged, or an acknowledgement has gone stale;
  - a cell that changed since the baseline has no passing scenario that covers it.
- G6: scenario checks and `existing_tests` commands may not name `~/` paths or existing
  files outside the project.
- The verifier receives the changed cells. From the requirement alone, it says what each
  cell should do and reports any disagreement.
- Superstates and parallel regions are removed from the control-model format and scripts.
- New scenario `job-lookup-cancel`, with eval cases for both hosts.

## Upgrading

```sh
claude plugin marketplace update hobin
claude plugin update hobin-feature@hobin
codex plugin marketplace upgrade hobin
codex plugin add hobin-feature@hobin   # install from the refreshed snapshot
```

In Codex, open `/hooks` in a new session and trust the changed `hobin-feature` Stop hook.
It now runs the control-model gate as well. Until you trust it, the skill runs the same
checks itself.
