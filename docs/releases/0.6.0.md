# 0.6.0: hobin-feature registers records structurally

**Status: on branch `fix/feature-hook-ledger-run` (PR #8), not released.**

| Plugin | Version |
|---|---|
| `hobin-feature` | 0.5.1 → 0.6.0 |
| others | unchanged |

`developing-features` SPEC 0.5.0 → 0.6.0. Investigation, measurements and decisions:
`docs/plans/2026-11-06-feature-hook-cross-repo-and-run-state.md`.

## Changes

- **No inference.** The Stop hook no longer reads shell text or walks the tree: PreToolUse stamps,
  record-name parsing of commands, the cwd walk and the git checked-out exemption are gone.
- **Registration through tool output.** `scenarios.mjs init|run|check <record>` and
  `compile-control-model.mjs --baseline|--changes|--gate <record>` print
  `hobin-feature-record: <absolute path>`. After every tool call the hook reads the tool's output
  (any shape; on Claude also a failure's error text) and registers each marked path that is
  absolute, exists and names a record file, in its own ledger. No session id in the environment
  and no temp directory shared with the scripts. Edit tools still register the exact path they
  wrote. A record in another repository is gated wherever it lives; a file a shell program writes
  some other way is not the session's.
- **`scenarios.mjs init <path>`** creates the record from the template and never overwrites.
- **Obligation.** Starting developing-features (Claude: the Skill tool or a
  `/developing-features` / `/hobin-feature:developing-features` prompt; Codex: a
  `$developing-features` prompt or reading this plugin's SKILL.md) makes Stop ask for a record:
  `init` for a new one, a foreground `check <path>` for an existing one, or a decline.
- **`scenarios.mjs decline --reason "<why>"`** prints `hobin-feature-decline: <why>` and releases
  that obligation for the session; Stop prints the reason. Records already registered must still
  pass.
- **Run state in the record.** `run` marks results `running` and writes
  `verification.run = { startedAt, lastProgressAt }`, saves after each result and deletes it when
  it ends (also on a throw), so an interrupted run never leaves earlier passes. `check` and Stop
  say the run has not finished: wait if it is still running, run it again if it stopped.
- **Checks run by `run`.** A failing check's output is re-printed with its marker lines
  neutralized, so fixture records a check creates never register.
- **Hooks.** Claude: UserPromptSubmit, PostToolUse and PostToolUseFailure on every tool, Stop.
  Codex: UserPromptSubmit, PostToolUse, Stop. Same script on both hosts.

## Known limitation

A background command's output never reaches the hook, so a record touched only by a background
run is not registered; Stop then asks for a foreground `check <path>`.

## Upgrading

Sessions that copied the template by hand now need `scenarios.mjs init`, a foreground
`run|check <record>` or an edit-tool write for the record to count; the skill text says so.
